# safe-delete multi-path file and tmp - Plan

## Goal Capsule

- Objective: an agent removes all of its leftover files in one tool call instead of one call per file, with every existing protection and restore path intact.
- Means: `file` and `tmp` modes accept 1..N paths, validate all first, then delete each (KTD1, KTD2).
- Authority: owner /goal 12.10 > this plan > code. Atom: dcfg-fmhy8.1 (epic dcfg-fmhy8).
- Stop conditions: any change outside `bin/safe-delete` lines of the `file)` and `tmp)` branches and `bin/safe-delete-test` → stop and report.
- Who finishes: worker via code-channel writes code and tests; the lead accepts, commits, and hands off to ship-post.

## Product Contract

### Summary

`safe-delete file` and `safe-delete tmp` take several paths in one call. If any path is refused, nothing is deleted.

### Problem Frame

Agents spend one tool call per deleted file. Root cause: `[[ $# -eq 1 ]] || refuse 'usage'` in the `file)` and `tmp)` branches (`bin/safe-delete:111`, `bin/safe-delete:114`).

### Requirements

- R1. `safe-delete file P1 [P2 ...]` and `safe-delete tmp P1 [P2 ...]` accept one or more paths; zero paths → `refuse 'usage'` (rc 2) as today.
- R2. All paths pass today's checks before the first deletion: `file` — `check_file`; `tmp` — `realpath -e` plus the `/tmp/*` and `!= /tmp` prefix test. Any refusal → rc 2, no path deleted.
- R3. After validation each path is deleted exactly as today: same stdout line per path (`удалено: … | основание: … | восстановить: safe-delete restore N` for `file`, `удалено: <p> | основание: tmp, без копии` for `tmp`) and one ledger row per path.
- R4. Duplicate paths in one call are deleted once (dedupe after `realpath`).

### Scope Boundaries

- Unchanged: `dir`, `worktree`, `branch`, `link`, `restore`, `purge`, `repo-autodelete`; `check_path`, `check_file`, `delete_file`, `git_file`, `log` bodies; the forbidden-zone list; managed deny in `/etc/claude-code`.
- `dir` stays single-path: one call already removes a whole directory.

## Planning Contract

### Key Technical Decisions

- KTD1. Two-pass loop inside each branch: pass 1 validates every argument, pass 2 deletes. Validation reuses existing functions; no new helper for one-time use.
- KTD2. `refuse` exits the script, so pass 1 failing at any argument already guarantees nothing was deleted.
- KTD3. A mid-pass-2 failure (I/O error) exits 1 as today; paths already deleted keep their ledger rows and restore numbers. No rollback.

### Assumptions

- `check_file` has no side effects besides setting `p` (verify in `bin/safe-delete:56-75` before use).

## Implementation Units

### U1. Multi-path `file` and `tmp`

- Goal: R1–R4.
- Files: `bin/safe-delete` (the `file)` and `tmp)` branches only), `bin/safe-delete-test`.
- Approach: replace `[[ $# -eq 1 ]]` with `[[ $# -ge 1 ]]`; pass 1 loops over `"$@"` running today's checks and collects resolved paths (dedupe); pass 2 loops over the collected list running today's delete body. Follow the style of the `dir)` branch (`bin/safe-delete:122-138`), which already validates all entries before deleting.
- Test scenarios (add to `bin/safe-delete-test`, follow its existing case style):
  1. `tmp` with 3 files under a temp dir in `/tmp` → rc 0, 3 lines starting `удалено`, none of the 3 files exist.
  2. `file` with 3 untracked files in the test sandbox → rc 0, 3 lines containing `restore`, `restore <N>` of one brings it back.
  3. `file` with one valid file and one path in a forbidden zone → rc 2, valid file still exists.
  4. `tmp` with one valid path and one path outside `/tmp` → rc 2, valid path still exists.
- Verification: `bin/safe-delete-test` exit 0.

## Verification Contract
