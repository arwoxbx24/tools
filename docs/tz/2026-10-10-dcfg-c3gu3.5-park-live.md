# ТЗ dcfg-c3gu3.5 — ship-post-test: opt-in сквозной смоук park-live на настоящем bd

Skills: superpowers:test-driven-development, caveman:surgical-patch, prod.

## U1 Факт
Тесты `park` (dcfg-c3gu3.2) идут на моке `bd`. Нужно одно доказательство, что настоящий `bin/ship-post` на отказе 71 сам создаёт инцидент настоящим `bd`.
Ручной стенд агента отклонён правами (агент не пишет исполняемые файлы). Стенд — часть `bin/ship-post-test`, запуск только явный.

## U2 Правка (только `bin/ship-post-test`)
1. Новая функция перед строкой `if [[ ${SHIP_POST_TEST_GROUP:-all} == review ]]; then`:
```bash
test_park_live(){
 [[ ${SHIP_POST_LIVE_BD:-0} == 1 ]] || { echo "SKIP park_live (SHIP_POST_LIVE_BD!=1)"; return 0; }
 local atom=${SHIP_POST_LIVE_ATOM:?SHIP_POST_LIVE_ATOM required} root=${SHIP_POST_LIVE_ROOT:-/root/workspaces/projects} real_bd=${SHIP_POST_LIVE_BD_BIN:-/root/.local/bin/bd} out inc i st lbl
 setup_submit park_live "claude/$atom-live"; commit_candidate "$atom" claude
 rm -f -- "$d/bin/bd"; ln -s "$real_bd" "$d/bin/bd"
 out=$(env HOME="$HOME" PATH="$d/bin:/usr/bin:/bin" SHIP_POST_TEST_DIR="$d" SHIP_POST_REPOS="$d/repo" SHIP_POST_STATE_DIR="$d/state" \
  SHIP_POST_BEADS_ROOT="$root" SHIP_POST_RETRY_SECONDS=1 BEADS_ACTOR='Claude Code' MOCK_SHIP_RC=71 \
  timeout --kill-after=2 60 "$d/bin/ship-post" 2>&1)
 for i in $(seq 1 50); do [[ -f $d/state/incidents/parked/$atom ]] && break; sleep 0.2; done
 inc=$(cat "$d/state/incidents/71" 2>/dev/null)
 echo "park_live: incident=$inc"
 st=$(cd "$root" && "$real_bd" show "$inc" --json 2>/dev/null | jq -r '.[0] | "\(.status) \(.priority) \(.issue_type) \((.labels // []) | join(","))"')
 lbl=$(cd "$root" && "$real_bd" show "$atom" --json 2>/dev/null | jq -r '.[0] | "\(.status) \((.labels // []) | join(","))"')
 echo "park_live: incident_show=$st atom_show=$lbl"
 [[ -n $inc && $out == *"ship-post: parked: $atom incident $inc"* && $st == "open 0 bug contour:delivery" && $lbl == "closed "*delivery-blocked* ]] && pass park_live || fail park_live "out=$out st=$st lbl=$lbl"
}
```
2. Диспетчер групп: добавить ветку `elif [[ ${SHIP_POST_TEST_GROUP:-all} == park-live ]]; then test_park_live` рядом с веткой `park`. В полный список (`else`) НЕ добавлять: в CI группа не идёт.

Ничего больше не менять. `bin/ship-post` не трогать.

## U3 Критерий
1. `bash -n bin/ship-post-test`.
2. `SHIP_POST_TEST_GROUP=park-live bash bin/ship-post-test | tail -3` без `SHIP_POST_LIVE_BD` — строка `SKIP park_live`, `failures=0`.
3. Живой прогон делает главный агент, не исполнитель: не запускать с `SHIP_POST_LIVE_BD=1`.
4. `SHIP_POST_TEST_GROUP=park bash bin/ship-post-test | tail -2` — `failures=0`.

## Факт после прогона 1
Живой прогон главного агента: `PASS park_live`, инцидент создан. Дефект ТЗ: `local ... root=${SHIP_POST_LIVE_ROOT:-...}` в `test_park_live` перекрывает глобальную `root` стенда, и `setup_submit` создал стенд в `/root/workspaces/projects/park_live` вместо временного каталога.
Правка (только `bin/ship-post-test`, только `test_park_live`): переименовать локальную `root` в `live_root` во всех трёх местах функции (объявление `local`, `SHIP_POST_BEADS_ROOT="$live_root"`, оба `cd "$live_root"`). Больше ничего не менять. Живой прогон не запускать.
Критерий: `grep -c 'live_root' bin/ship-post-test` ≥ 4; `grep -n ' root=' bin/ship-post-test` не находит строку внутри `test_park_live`; `bash -n bin/ship-post-test`.
