# ТЗ dcfg-2cn8h — safe-delete: состояние процесса при пробеле в comm

## U1
Разведка — repowise (индекс tools: `tools/bin/code-memory-enable` при отсутствии).

Дефект: `bin/safe-delete:143` в цикле проверки cwd процессов (форма `worktree`) читает состояние процесса как `awk '{print $3}' "/proc/$pid/stat"`. Формат `/proc/PID/stat`: `pid (comm) state …`; comm может содержать пробелы (`(mongosh mongodb)`), тогда `$3` = `mongodb)`, проверка зомби (`== Z`) не срабатывает и обёртка отказывает «нечитаемый cwd процесса: PID» на зомби, у которого cwd нет.

Правка (минимальная, одна строка в `bin/safe-delete:143`): брать состояние как первое поле после последней `) ` в `/proc/$pid/stat` (например `s=$(<"/proc/$pid/stat"); s=${s##*) }; s=${s%% *}`). Остальную логику строки не менять: живой процесс с cwd внутри worktree по-прежнему даёт отказ «процесс использует worktree», нечитаемый cwd живого не-зомби — отказ «нечитаемый cwd».

Тест (в `bin/safe-delete-test`, новый пункт после последнего): извлечь функцию разбора или проверить строку так, чтобы
1) строка stat `123 (mongosh mongodb) Z 1 …` → состояние `Z` (пропуск);
2) строка stat `123 (bash) S 1 …` → `S` (не пропуск);
3) существующие пункты T1–T17 проходят без изменений.
Если вынос функции нужен для теста — допустим, без других изменений.

Запреты: без `rm -rf`, без правок вне `bin/safe-delete` и `bin/safe-delete-test`, список запретных зон обёртки не сужать.

Проверка: `bin/safe-delete-test` → все PASS, rc 0.
