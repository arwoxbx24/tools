# TZ — parked atom re-run backoff (atom dcfg-c75sy.3)

Plan: projects `docs/tz/2026-10-16-dcfg-c75sy-ship-post-parked-loop.md` U1 (R1-R3, KTD1). Разведка — repowise (codebase-memory `search_graph`/`get_code_snippet`), затем `grep -n`; Read только правимых диапазонов. Индекс: repowise/CBM проверен, нет — `tools/bin/code-memory-enable`.

Причина: атом с INFRA-кодом (например 30) паркуется (`bin/ship-post:439-461`, файл `$SHIP_POST_STATE_DIR/incidents/parked/<atom>`), но `bin/ship-post:651` пропускает только коды `10|50|80`. Поэтому `deliver_one` (`:661`) запускает новый `ship --handover` на каждом проходе (~70 с) для того же SHA.

## U1
Файлы: `bin/ship-post`, `bin/ship-post-test`. Других файлов не трогать.
1. `bin/ship-post`: рядом с `SHIP_POST_SINCE` (строка 10) добавить `SHIP_POST_PARKED_RETRY_SECONDS=${SHIP_POST_PARKED_RETRY_SECONDS:-3600}`.
2. `bin/ship-post`, строка 651: когда `$rf.failed` существует и код не `10|50|80`, а файл `$SHIP_POST_STATE_DIR/incidents/parked/$atom` существует:
   - его возраст (`now - mtime`) меньше `SHIP_POST_PARKED_RETRY_SECONDS` → `skip=$((skip+1)); continue`;
   - иначе `touch` этого файла и дальше по существующему пути (повторный запуск один раз).
   Без parked-файла поведение не меняется. Путь `ack_delivery` (`:485-500`) не трогать.
3. `bin/ship-post-test`, функция `test_park` (~строка 689): добавить проверки, по образцу существующих в этой функции (моки `ship`/`bd`, `$d/state/incidents/parked/<atom>`):
   - PB1: свежий parked-файл + `<rf>.failed` = 30 → один проход (`--once` или как в соседних проверках) не запускает `ship --handover`; итоговая строка `skip=` больше на 1.
   - PB2: parked-файл старше лимита (`SHIP_POST_PARKED_RETRY_SECONDS=1` и `touch -d '-10 seconds'`) → handover запущен ровно один раз, mtime parked-файла обновлён.
   - Существующая проверка `unpark_ok` (доставленный атом теряет parked-файл и метку) должна остаться зелёной.
