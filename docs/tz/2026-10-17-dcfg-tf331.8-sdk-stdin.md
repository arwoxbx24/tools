# TZ dcfg-tf331.8 — sdk-agent: pass the prompt on stdin, not as one argv

FILE: bin/sdk-agent
FILE: bin/sdk-agent-test

## Defect (reproduced 17.10)
`code-channel auto` on a TZ listing bin/ship-post (52 KB) + bin/ship-post-test (83 KB) failed:
`bin/sdk-agent: line 198: /usr/bin/env: Argument list too long` → `engine returned no JSON result` (rc 4).
Cause: bin/sdk-agent:196 runs `... "$engine" "${args[@]}" "$prompt" < /dev/null` — the whole prompt (task + embedded files, built at :446-457 and :495) is one argv string; Linux caps one argv string at 128 KB.

## Official contract (docs)
- https://code.claude.com/docs/en/headless: "Piped stdin is capped at 10MB. If you exceed the cap, Claude Code exits with a clear error and a non-zero status."
- https://code.claude.com/docs/en/cli-reference: `cat logs.txt | claude -p "explain"` — piped stdin content plus a short positional instruction.

## Change
1. bin/sdk-agent:196: feed `$prompt` on stdin (here-string `<<<"$prompt"` instead of `< /dev/null`) and pass a short fixed positional instruction instead of `"$prompt"`, e.g. `"Follow the task provided on stdin exactly."`. Nothing else in the call changes (env -u list, key loading, args, model pin, budget, ledger).
2. bin/sdk-agent-test: one new check in the existing style (stub engine via SDK_AGENT_ENGINE, :16): a ~200 KB prompt reaches the stub on stdin intact (byte count equal) and the run does not fail with "Argument list too long". Existing checks unchanged.

## Constraints
- Minimal diff. Keep `engine_override_test_only` (:234-237) true: SDK_AGENT_ENGINE stays read only inside the SDK_AGENT_TEST block.
- Do not change budget, cap, model pin, tools, key handling, permissions.
- No secrets read or printed; no network in tests; do not run heavy suites.
