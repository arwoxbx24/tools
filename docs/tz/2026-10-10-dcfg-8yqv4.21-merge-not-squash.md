# ТЗ dcfg-8yqv4.21 — ship: слияние PR через --merge вместо --squash (spec:099 v6 U13, FR-033, ADR-26)

## U13
Спека: `/root/workspaces/projects/specs/099-ship-dev-prod/spec.md` §«v6» — прочитать раздел целиком до правки.

Причина: после squash-слияния родителя дочерние ветки стека конфликтуют (PR tools #170–#174). ADR-26: `gh pr merge --merge --match-head-commit <SHA>`. Официальный мануал https://cli.github.com/manual/gh_pr_merge: «`--merge`: Merge the commits with the base branch», «`--match-head-commit`: Commit SHA that the pull request head must match to allow merge».

Правка:
1. `bin/ship` (строка с `gh pr merge … --squash`) и `bin/ship-promote` (то же): заменить `--squash` на `--merge`. Больше ничего в этих строках не менять.
2. `bin/ship-test`: заглушка gh, которая имитирует squash (`git merge --squash`, около строк 87–88), — имитировать `--merge` настоящим merge-коммитом (`git merge --no-ff`). Добавить один тест стека: ветка A, ветка B поверх A; доставить A, затем B; B сливается без конфликта (rc 0). Тест должен падать на старом коде (`--squash`) и проходить на новом. Проверить это и написать в отчёте.
3. `docs/ship-post-ARCHITECTURE.md`: одна строка в §6 или в описании шага merge — PR атома сливается merge-коммитом (ADR-26), стек веток остаётся потомками `main`.

Не менять: `bin/ship-post`, `bin/git-sync`, `bin/git-auto-lib`, путь dev→prod fast-forward (FR-011).

Критерии (исполнитель запускает сам и прикладывает вывод):
1. `grep -c -- '--squash' bin/ship bin/ship-promote` → 0 и 0.
2. `bash bin/ship-test` → rc 0; новый тест стека PASS; на старом `bin/ship` (из `git show origin/main:bin/ship`) он FAIL.
3. `bash bin/ship-doc-check origin/main` → rc 0.
4. Коммит не делать (`.git` только для чтения) — отчёт: дифф `--stat` и выводы команд.
