# TZ dcfg-yvrzy — safe-delete: one batch pipeline for 1/10/1000 files (spec 007 v4)

## U1
FILE: bin/safe-delete
FILE: bin/safe-delete-test

Problem (measured 17.10): `safe-delete --bk /tmp/sdb/bk file <1000 files>` → wall 49.61 s (≈50 ms/file). Cause: every file runs its own processes (check_file twice → realpath; mkdir, cp, touch, cmp, sha256sum, 2× date, 2× log where log does `wc -l` over the whole ledger (22018 lines); git files ≈9 git forks + awk over the ledger), dir/worktree with N args re-exec the script per arg.

Success predicate (over the artifact): the same command on 1000 files of /tmp fixtures finishes in ≤5 s; process count per call does not grow with N (batch commands only); stdout, ledger and restore behave exactly as before. A plan, partial batching of one mode or a "should be faster" claim does not count.

### Design (all paths go through one pipeline: file, dir, worktree)
1. Validate all first (fail fast, all-or-nothing): resolve all paths with ONE `realpath -e -z` call; run the existing pure-bash checks of check_path/check_file per path WITHOUT forks (no realpath inside the loop); any refusal → rc 2 before anything is copied or deleted. Dedupe as now (:135-139). Each check runs once per path (no second check inside delete).
2. Classify git-pinned vs copy in batch per repo: one `git rev-parse --show-toplevel` per distinct directory (cache by dir), then per repo ONE each of: `git ls-files -s -v -z -- <paths>` (mode 100644/100755, tag H), `git check-attr filter -z --stdin` (not lfs), `git hash-object --no-filters --stdin-paths`, `git ls-tree -r -z HEAD -- <paths>` (blob equals HEAD). Same rules as git_file (:44-60), no per-file git call. Symlink rule (:48) kept.
3. Git-pinned files: ONE `git update-ref --stdin` per repo creating refs/safe-delete/<ts>-<blob12> (unique per file), as now.
4. Copy files: backup into the SAME path formula as now ($BK/files/<YYYYMMDD>/<abs path>, `.HHMMSSN` suffix if it exists). Use ONE `cp -al --parents` style hard-link batch when $BK is on the same filesystem (same `stat -c %d`), else ONE `cp -p --parents` batch. Then ONE `touch` over all backup paths (purge counts 14 days from deletion, :105). Verify in batch: hard link → same inode via ONE `stat -c '%d:%i'` over both lists; copy → ONE `sha256sum` over both lists compared. sha256 of every backup via ONE `sha256sum` (ledger column 6, as now).
5. Ledger: keep the exact TSV columns and line types (file … backup-ok, file … deleted, git …). Write lines with ONE flock section per phase: inside the lock count lines once (wc -l), append all lines in one write, derive each file's restore id = its own line number. Remove the per-call `wc -l` from log() hot path for batches (single-path callers may keep log()).
6. Delete: ONE `rm -f --` via `xargs -0` (or one rm with all args) after backups and backup-ok lines are written; then the deleted lines; then print one line per file exactly as now: `удалено: <p> | основание: копия <copy> | восстановить: safe-delete restore <N>` or `удалено: <p> | основание: git <ref> | восстановить: safe-delete restore <N>`.
7. dir: entries checked via one find listing + the same fork-free checks; files go through the pipeline; links and empty dirs as now. Multi-arg dir/worktree (:115-121): run in-process, no re-exec per argument; keep `итог: ok=N, failed=M` and rc.
8. tmp: ONE `rm -r --` over all paths, ledger lines in one write, same output lines.
9. Cache without copy (owner word 17.10: "кэш … всё что попадает под временные … не должно попадать под программу и можно разрешить удалять его прямым образом"): new mode `safe-delete cache <path>...`, and `dir <path>` auto-routes to it when the path qualifies. A path qualifies when check_path passes (roots and bans unchanged) AND one of its segments is in the closed list: `.cache`, `__pycache__`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `node_modules`, `.npm`, `.parcel-cache`, `.turbo`, or the exact pair `wp-content/cache` (or the path is under /root/.cache); the generic name `cache` alone and `.next` do NOT qualify (may hold uploads or build output) AND it contains no git-tracked file (ONE `git ls-files -z` per repo; tracked → not cache: `cache` refuses rc 2, `dir` falls back to the copy pipeline). Qualifying paths: ONE `rm -r --` over all, ledger line per path `cache <p> - - - - deleted` in one write, stdout `удалено: <p> | основание: кэш, без копии`. Any non-qualifying path in a `cache` call → rc 2 before deleting anything. Add `cache` to the usage lines (:3, :111).
Out of scope: restore, branch, purge, link, repo-autodelete logic; roots and bans; ledger format of existing types; output text of existing types.

Principles: KISS, YAGNI, DRY (one pipeline function for file/dir/worktree), fail fast, minimal diff; no refactor of out-of-scope modes; no new dependencies (coreutils, findutils, git only).
