# ТЗ dcfg-1ci20.8 U0a — обёртка `bin/beget-api` (read-only диагностика Beget API)

Исполнитель пишет код сам, `code-channel` не вызывает. Разведка — repowise (для tools индекса нет → `grep -n`).

## Цель
Агенты вызывают Beget API по имени метода, не видя секретов, и получают полный ответ API без кредов: `status`, `error_code`, `error_text`, `answer`.
Повод: `forms-dns-switch.sh status` возвращает `api_error UNKNOWN_ERROR`, текст ошибки не виден, причина неизвестна.

## Границы
- Новый файл `bin/beget-api` (bash, ≤40 строк). Других файлов не трогать.
- Использование: `bin/beget-api <раздел/метод> [input_data-json]`; без второго аргумента — `{}`.
- Секреты: `BEGET_LOGIN`, `BEGET_API_PASSWORD` из `/root/workspaces/secrets/projects/beget.env` (путь переопределяется `BEGET_ENV_FILE`), загрузка `. "$BEGET_ENV_FILE"` только если переменные пусты — как `scripts/schedulers/forms-dns-switch.sh:20`.
- Вызов — как `scripts/schedulers/forms-dns-switch.sh:40`: конфиг curl через stdin (`curl -s --max-time 15 -K -`), пароль не в argv, `data-urlencode` для login, passwd, input_format=json, output_format=json, input_data.
- Вывод: тело ответа API через `jq .` (stdout). Если ответ не JSON — печатать `non-json response, http=<код>` и длину тела, без тела.
- Код выхода: 0 — `.status=="success"` и (`.answer.status` отсутствует или `=="success"`); 1 — ошибка API; 2 — сеть/не JSON; 64 — нет аргумента метода.
- Метод проверяется регуляркой `^[a-z]+/[A-Za-z]+$`, иначе 64.
- `set -euo pipefail`. Нет `set -x`. Логин и пароль никогда не печатаются.
- Запрещено: write-методы в тесте, правка секретов, правка `forms-dns-switch.sh`, сеть в тесте.

## v2 (08.10) — пустой логин после загрузки файла
Факт: `bin/beget-api user/getAccountInfo` → `"error_text": "Invalid request, login not provided"`, `UNKNOWN_ERROR` — после `. "$BEGET_ENV_FILE"` переменная `BEGET_LOGIN` пуста (в файле другое имя ключа).
Правка `bin/beget-api` (файл уже есть, ≤50 строк):
- После загрузки, если `BEGET_LOGIN` или `BEGET_API_PASSWORD` пусты: печатать в stderr `missing BEGET_LOGIN|BEGET_API_PASSWORD in <путь>; keys: <имена>` и выйти с кодом 3. Имена ключей — только левая часть до `=` строк вида `[export ]ИМЯ=`, через `sed -nE 's/^[[:space:]]*(export[[:space:]]+)?([A-Za-z_][A-Za-z0-9_]*)=.*/\2/p'`. Значения никогда не печатать.
- Тест на моке (временный файл env в mktemp): файл с `BEGET_USER=x` и `BEGET_PASS=y` → rc 3, stderr содержит `keys: BEGET_USER BEGET_PASS` и не содержит `x`/`y` как значения.

## Критерии приёмки
1. `bash -n bin/beget-api` → rc 0; `wc -l bin/beget-api` → ≤40.
2. `bin/beget-api` без аргументов → rc 64; `bin/beget-api 'bad method'` → rc 64.
3. `grep -nE 'set -x|echo .*PASSWORD|printf .*PASSWORD' bin/beget-api` → только строка конфига curl в stdin (как forms-dns-switch.sh:40), иных совпадений 0.
4. Живой read-only вызов (делает Claude после сдачи): `bin/beget-api user/getAccountInfo` → JSON с `status` и, при ошибке, `error_text`.

## Паспорт источников
- https://beget.com/ru/kb/api/obshhij-princzip-raboty-s-api (Tavily extract 08.10): «Если запрос завершился с ошибкой, то поле status имеет значение error. В этом случае рядом с этим полем будут находится поля error_text(текст ошибки) и error_code»; коды AUTH_ERROR, INCORRECT_REQUEST, NO_SUCH_METHOD; в result — INVALID_DATA, LIMIT_ERROR, METHOD_FAILED. UNKNOWN_ERROR в документации нет.
- Образец вызова: `scripts/schedulers/forms-dns-switch.sh:20,40-42` (атом dcfg-1ci20.3, PR #134).
