## Уточнение 1 (главный агент, 10.10) — ADR-29: закрыт = доставляется, молчаливых skip нет
ЗАМЕНЯЕТ пункты 1–3 выше (новые задачи не создавать). Разведка: `repowise context bin/ship-post::scan_repo bin/ship-post::record_failure --path /root/workspaces/tools`.
В `scan_repo` три skip закрытого атома (`no assignee`, `tz not a file in worktree`, branch mismatch):
1. `no assignee` → взять исполнителя из трейлера `Agent:` последнего коммита ветки (`claude` → `Claude Code`, `codex` → `Codex`), `bd update <atom> --assignee <имя>`, продолжить доставку. Нет трейлера → п.3.
2. `tz not a file in worktree` → если путь из трейлера `ТЗ:` (без `#…`) — существующий абсолютный файл, принять его и продолжить. Иначе → п.3.
3. Любой оставшийся skip закрытого атома с веткой `claude/<atom>-*` или `codex/<atom>-*` → `record_failure` с кодом 10 и причиной skip.
`record_failure` для кодов 10/20/24/30/40/50/60/80: `bd reopen <atom>` + `--append-notes` ЭТОГО атома одной строкой `ship-post exit <код>: <причина>; действие: <из таблицы кодов v6>`; для 50 — файлы `CONFLICT` из `$key.log`. Общую задачу `[ship-post] delivery failure …` больше не создавать, `dep add` не делать. Временные 23/70/75 — без изменений.
Тесты группы `u15`: (а) закрытый атом без assignee, с `Agent: claude` → доставлен, assignee `Claude Code`; (б) ТЗ вне worktree, файл существует → доставлен; (в) отказ 50 → reopen + заметка атома с `exit 50`, ни одного `create`.
Строка в `docs/ship-post-ARCHITECTURE.md` §6: ADR-29.
