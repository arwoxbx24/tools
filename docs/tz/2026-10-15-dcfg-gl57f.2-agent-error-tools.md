## U2 — `bin/route-hint` (PostToolUseFailure hook, non-blocking)
Goal: after an ordinary failed command, Claude sees the sanctioned route next to the failure (owner decision 2026-10-15: failures, not denials; denials fire no hook).
- Input: hook JSON on stdin. Real payload captured 2026-10-15: `{"hook_event_name":"PostToolUseFailure","tool_name":"Bash","tool_input":{…},"error":"Exit code 2\nls: cannot access '/nonexistent-claude-3421': No such file or directory",…}`.
- Rules file: `ROUTES_FILE` (default `/root/workspaces/projects/.claude/rules/routes.json`), shape `{"routes":[{"id":…,"kind":"deny"|"failure","error_regex":…,"route":…}]}`; use only rows with `kind=="failure"`; first row whose `error_regex` matches `.error` (jq `test()`) wins.
- Output on a match, exactly the documented form (https://code.claude.com/docs/en/hooks, "Add context for Claude": "Return `additionalContext` inside `hookSpecificOutput` alongside the event name"; PostToolUseFailure context appears "next to the tool result"):
  `{"hookSpecificOutput":{"hookEventName":"PostToolUseFailure","additionalContext":"route-hint (<id>): <route>"}}`
- No match, missing or broken rules file, missing `.error`, any jq failure → print nothing, rc 0. The hook never blocks and never exits non-zero (fail open). Runtime < 1 s.
- Test `bin/route-hint-test`: temp routes file with one failure row `No such file` and one deny row; payload with that error → stdout JSON with `hookEventName=="PostToolUseFailure"` and the route text; payload with unmatched error → empty stdout rc 0; `ROUTES_FILE=/nonexistent` → empty stdout rc 0; deny row text never printed.
Acceptance: `bin/route-hint-test` PASS line.

## U4 — `bin/agent-errors-baseline` + weekly pm2 job
Goal: one command (<60 s) prints the weekly error rates against the 4 owner targets.
- Args: `--days N` (default 7), `--corpus DIR` (default `/root/.claude/projects`). Files: `find DIR -name '*.jsonl' -mtime -N -size +1k`; one jq pass per file batch (`find … -exec jq … {} +`), no per-line shell loops.
- Pairing (same as the research doc): every `tool_use` (`.message.content[]|select(.type=="tool_use")`: id, name, `.input.command`) joined with its `tool_result` (`.message.content[]|select(.type=="tool_result")`: `tool_use_id`, `is_error`, content text).
- Measures: `bash_calls`, `bash_errors` (`is_error==true`), `bash_rate`; `denials` = Bash results whose text contains `has been denied`, `denial_rate` over bash_calls; `path_errors` = error results of Bash/Read whose text contains `No such file or directory` or `does not exist`; `injected_chars` = sum of `(.attachment.content|tostring|length)` for records with `.type=="attachment"` and `.attachment.type` in `hook_success`, `hook_additional_context`, plus `subagent_injected_chars` = the same sum over files under `*/subagents/*`.
- Targets (owner, 2026-10-15) printed as PASS/FAIL lines: `bash_rate<=3%`, `denial_rate<=0.4%`, `path_errors<=5` per 7 days (scale by days/7), `injected_chars<=50% of baseline` where baseline = 2846684 chars per 7 days (research doc: 5693368 over 14 days; scale by days/7). Last line: `targets=4 pass=<n> fail=<m> secs=<elapsed>`. rc 0 always (it reports, it does not gate).
- `ecosystem.config.js`: add app `agent-errors-weekly`: script `bin/agent-errors-baseline`, `cron_restart: "0 6 * * 1"`, `autorestart: false`, output to the logs dir the file already uses for other cron apps; follow an existing cron app entry exactly.
