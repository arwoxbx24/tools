## Интерфейс (контракт `specs/103-arwox-forms-hybrid-failover/contracts/dns-route.md` §«Интерфейс переключателя»)
`forms-dns-switch.sh status|apply normal|apply outage [--fqdn <fqdn>]`

Окружение (всё с умолчанием, кроме секретов): `DNS_FQDN=forms.arwox.ru` (`--fqdn` главнее); `DNS_GW_CNAME=d5dn462s09a9dpofvl2d.6brbn2wz.apigw.yandexcloud.net`; `BEGET_IP` (пусто → `apply outage` даёт `refused precheck no BEGET_IP`, код 3; `status` с пустым `BEGET_IP` считает A-запись `foreign`); `BEGET_API=https://api.beget.com/api`; `GUARD_STATE_DIR=/root/workspaces/tools/scripts/schedulers/state` (как сторож, `forms-gw-guard.sh:12`); `BEGET_ENV_FILE=/root/workspaces/secrets/projects/beget.env` — файл со строками `BEGET_LOGIN=` и `BEGET_API_PASSWORD=`, подключается через `.` только если переменные пусты и файл существует; значения никогда не печатаются и не логируются. `TG_BOT_TOKEN`, `TG_CHAT_ID` — из окружения (pm2 подаёт их сторожу, `forms-gw-guard.sh:4`); пусто → уведомление пропускается со строкой в лог, код выхода не меняется.

Вывод — ровно одна строка в stdout: `normal` | `outage` | `foreign` для `status`; `switched normal→outage` | `switched outage→normal` | `noop <mode>` | `refused precheck <причина>` | `foreign` | `api_error <код>` для `apply`. Лог — в stderr через `log()` того же вида, что у сторожа (`forms-gw-guard.sh:20`). Коды выхода: 0 — switched, noop, `status` normal или outage; 2 — ошибка API, блокировка занята, контрольное чтение не сошлось; 3 — refused; 4 — foreign; 1 — неверные аргументы.

## Логика
1. Вызов API — одна функция `beget <раздел/метод> <input_data-json>`: `curl -s --max-time 15 -K -` с конфигом на stdin (как сторож, `forms-gw-guard.sh:53`): `url = "$BEGET_API/<раздел/метод>"`, `data-urlencode = "login=$BEGET_LOGIN"`, `data-urlencode = "passwd=$BEGET_API_PASSWORD"`, `data-urlencode = "input_format=json"`, `data-urlencode = "output_format=json"`, `data-urlencode = "input_data=<json>"`. Пароль не попадает в argv. Успех = `.status=="success" and .answer.status=="success"` → функция печатает `.answer.result`. Иначе код ошибки = `.error_code // .answer.errors[0].error_code // "NET"` (curl rc≠0 или не-JSON → `NET`).
2. Режим из `dns/getData {"fqdn":"<fqdn>"}`: `.records.CNAME[0].value` без точки на конце равен `DNS_GW_CNAME` → `normal`; `.records.A[0].value` равен непустому `BEGET_IP` → `outage`; всё иное (нет записей, другая CNAME, другой A, оба типа сразу) → `foreign`. Форма группы CNAME в примере ответа документации не показана — допущение по симметрии с входом `changeRecords`; живой `status` и семантика «оба типа сразу» измеряются в U0, здесь не проверяются. Это допущение — часть паспорта источников: вызов `dns/getData` разрешён, форму записи задаёт заглушка теста; статус `blocked` по этой причине не ставить. Результат атома — файлы в worktree и прогон теста; текстовый ответ без изменённых файлов = провал атома.
3. Счётчик API — `state/forms-dns.<fqdn>.json` вида `{"api_fail":N,"notified":{"<type>":<epoch>}}`: каждая ошибка API → `api_fail+1`; ровно при `api_fail==3` → одно уведомление типа `api_fail`; успех API → `api_fail=0`. После ошибки API команда завершается кодом 2 без `changeRecords`.
4. Уведомление `notify <type> <text>` — Telegram `sendMessage` через `curl -s --max-time 10 -K -` (`url`, `data-urlencode chat_id`, `data-urlencode text`): тот же транспорт, что `forms-gw-guard.sh:48-55`; дебаунс 6 ч по `notified.<type>` в файле п.3 (не `state.json` сторожа — чужой писатель). Типы: `foreign`, `refused`, `api_fail`. Дубль транспорта осознан: комментарий `# ponytail: notify повторяет сторож; общий файл при третьем потребителе`.
5. `status`: п.2 → печать режима; код 4 при foreign, 2 при ошибке API.
6. `apply outage`: режим `foreign` → уведомление `foreign`, код 4; `outage` → `noop outage`, код 0; `normal` → а) снимок `state/forms-dns.snapshot.<fqdn>.json` = результат `dns/getData` как есть, только если файла ещё нет (один раз, ADR-103-11); б) предпроверка `curl -sI --max-time 10 --resolve "<fqdn>:443:$BEGET_IP" "https://<fqdn>/"` → строка статуса с кодом `302` и заголовок `location: https://arwox.ru/#contact` (регистр имени заголовка любой); провал → stdout `refused precheck <код или причина>`, уведомление `refused`, код 3, ноль `changeRecords`; в) `dns/changeRecords {"fqdn":"<fqdn>","records":{"A":[{"priority":10,"value":"<BEGET_IP>"}]}}`; г) контрольный `dns/getData` должен дать `outage`, иначе stdout `api_error verify`, код 2; д) stdout `switched normal→outage`, код 0.
7. `apply normal`: `foreign` → код 4; `normal` → `noop normal`; `outage` → снимок (если файла нет) → `dns/changeRecords {"fqdn":"<fqdn>","records":{"CNAME":[{"priority":10,"value":"<DNS_GW_CNAME>"}]}}` → контрольный `getData` = `normal` → `switched outage→normal`. Предпроверки нет: решение о возврате принимают сторож и наблюдатель (два успеха и выдержка, U2/U4).
8. Блокировка: `flock -n` на `state/forms-dns.<fqdn>.lock`; занято → stdout `api_error locked`, код 2.
9. Живых вызовов `api.beget.com`, `api.telegram.org` и DNS в атоме нет: тесты только с `BEGET_API` на заглушке; `BEGET_ENV_FILE` в тесте — временный файл с фиктивными значениями.
