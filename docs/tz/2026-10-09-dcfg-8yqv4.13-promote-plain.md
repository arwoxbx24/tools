# ТЗ dcfg-8yqv4.13 — ship-promote: перенос в prod для plain (открытый PR атома) на проверенном SHA; guarded — prod-hold без отказа

## U1 — второй путь переноса и снятие отказа skip
Разведка — repowise; индекс: repowise/CBM проверен, нет — `tools/bin/code-memory-enable`.

Причина (spec:099 v4, ADR-17, ADR-19, FR-028, FR-029; `projects/specs/099-ship-dev-prod/spec.md` раздел v4). После атома dcfg-8yqv4.12 ship в репо без CI заканчивает работу так: состояние `wait-owner`, PR открыт, `refs/dev-ready/<ветка>` = проверенный SHA. Перенести такой атом в prod нечем: `bin/ship-promote` в режиме one отказывает (`leave 10 mode`), а репо с `ga_skip_reason` получают отказ `leave 10 skip`.

Решение (ADR), правка только `bin/ship-promote`:
1. Строку `[[ -z "$(ga_skip_reason "$name")" ]] || leave 10 skip` удалить. Проверку перенести после `read -r mode base prod`: при `[[ $(ga_class "$name" "$mode") == guarded ]]` (функция из dcfg-8yqv4.12) — `echo "prod:hold guarded $reason — защиту снимает только слово владельца по закону" >&2; leave 0 prod-hold`. При `mode == two` (защищённый проект после онбординга, spec:099 v5) выполнять обычный `promote()` с обязательной цитатой. Тест: `stroyremont` с `origin/dev` и цитатой → перенос идёт.
2. Проверка статуса атома. В режиме two — как сейчас. В режиме one допускается и `closed`, потому что ship-post закрывает атом при сдаче. Запрет повтора по заметке `^promote:` остаётся в обоих режимах.
3. Ветку `if [[ $mode == one ]]` с `leave 10 mode` заменить функцией `promote_plain`, которую вызывает `ga_lock "$name" 60 promote_plain`. Шаги:
   - `pr=$(gh pr list -R "$slug" --state open --json number,headRefName,headRefOid,title --jq "[.[]|select(.title|startswith(\"$atom:\"))][0]")`. Сбой — `leave 70 pr-read`; пусто — `echo 'ship-promote: у атома нет открытого PR' >&2; leave 10 no-pr`;
   - `sha=$(git -C "$repo" rev-parse --verify -q "refs/dev-ready/<headRefName>")`. Пусто или не равно `headRefOid` → `echo 'ship-promote: SHA PR не тот, что проверен в dev' >&2; leave 50 sha`;
   - `gh pr merge <num> -R "$slug" --squash --match-head-commit "$sha"`. Сбой — `leave 50 merge`;
   - `merge_sha=$(gh pr view <num> -R "$slug" --json mergeCommit --jq .mergeCommit.oid)`, затем `bd note "$atom" "promote: $merge_sha pr=<num> dev=$sha quote=$quote"`;
   - `ga_live_sync "$name" "$merge_sha" "$(( $(date +%s) * 1000 ))" "$reload"`, код и шаг — как в `promote()`;
   - атом `open` или `in_progress` → `bd close` с причиной `promote <merge_sha>`. Закрытый не трогать;
   - `leave 0 promoted`.
4. Режим two (`promote()`) не менять. Цитата обязательна в обоих режимах, как сейчас: это шлюз `owner`.
5. Usage и строку `exit codes` дополнить: `0 prod-hold`, `10 no-pr`, `50 sha/merge`.

Тест — `bin/ship-test.d/`, новый файл `u11-promote-plain.sh` в стиле соседних, следующий свободный номер. Фикстура — репо режима one с открытым PR атома (stub `gh`), `refs/dev-ready/<ветка>` = вершина ветки:
- с цитатой → rc 0, в журнале stub `gh` есть `pr merge … --match-head-commit <sha>`, в bd-журнале `promote:`;
- `refs/dev-ready` ≠ `headRefOid` → rc 50, merge 0;
- нет открытого PR → rc 10 `no-pr`;
- `--quote ''` → rc 10, вызовов `gh` 0;
- репо `stroyremont` → rc 0, `prod-hold`, вызовов `gh` 0;
- повтор после успешного переноса (заметка `promote:`) → rc 10.

Прочие проверки не ослаблять.

Дока: обновить в `docs/ship-post-ARCHITECTURE.md` раздел о переносе в prod (два пути: `staged` — перемотка, `plain` — merge PR на проверенном SHA). Иначе CI-гейт `ship-doc-check` отклонит PR.

Запреты: только `bin/ship-promote`, `bin/ship-test`, `bin/ship-test.d/*`, `docs/ship-post-ARCHITECTURE.md` и этот ТЗ. Без `--force`, `reset --hard`, `rm -rf` вне `/tmp`. Принципы: KISS, YAGNI, fail fast.

Критерии:
1. `bash -n bin/ship-promote` → rc 0.
2. `bash bin/ship-test` → `PASS N/N`, rc 0.
3. `grep -c 'leave 10 mode' bin/ship-promote` = 0; `grep -c 'leave 10 skip' bin/ship-promote` = 0; `grep -c 'match-head-commit' bin/ship-promote` ≥ 1.

Паспорт: `bin/ship-promote:1-82`; `bin/ship:136-170` (поиск PR и merge — образец); `bin/git-auto-lib` (`ga_lock`, `ga_live_sync`, `ga_ctx`).
