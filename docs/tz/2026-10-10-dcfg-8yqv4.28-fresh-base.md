Разведку НЕ делать широко — якоря даны. Править ТОЛЬКО `bin/ship`, `bin/git-auto-lib`, новый `bin/ship-test.d/u17-base-move.sh`, `docs/ship-post-ARCHITECTURE.md`. `bin/ship-post*` НЕ трогать.

Риск: CI PR прошёл на старом `origin/<base>`; после чужого слияния слияние без перепроверки может сломать main. GitHub: «By default, a workflow only runs when a pull_request event's activity type is opened, synchronize, or reopened.» (docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows).

1. `bin/ship:105` (`locked_core`, после `g fetch -q origin "$base" || return 70`): `ci_base=$(g rev-parse origin/$base)` — глобальная переменная (без `local`).
2. `bin/ship:198-199` (`ga_lock "$name" 60` + `gh pr merge`): перед `gh pr merge`, под этим же замком, цикл до 5 кругов:
   - `g fetch -q origin "$base"` (ошибка → `leave 70 fetch`); `new=$(g rev-parse origin/$base)`.
   - `new == ci_base` → слияние как сейчас.
   - иначе `moved=$(g diff --name-only "$ci_base" "$new")`, `mine=$(g diff --name-only "$new...<head>")` (head = `${expected_head:-$(git -C "$wtr" rev-parse HEAD)}`). Если пересечения `moved`∩`mine` нет И ни один файл из `moved` не совпадает с `^bin/(ship|ship-post|git-sync|git-auto-lib|git-state)$|^bin/ship-test$` (тот же список, что `.github/workflows` строка 26) → печать `ship: base moved <ci_base:0:7>..<new:0:7>, disjoint, no re-CI` и слияние.
   - иначе печать `ship: base moved <old>..<new>, re-CI #<num> round <k>`; снять замок (как снимает `ga_lock` — посмотреть `bin/git-auto-lib:ga_lock`, при необходимости вынести слияние в функцию и звать `ga_lock "$name" 60 <функция>`); `since=$(date -u +%Y-%m-%dT%H:%M:%SZ)`; `gh_or70 gh pr close "$num" -R "$slug"`; `gh_or70 gh pr reopen "$num" -R "$slug"`; `ci_base=$new`; `ga_ci_wait pr "$slug" "$num" "<head>" "$since"` (30 → `leave 30 ci-absent`, иное ≠0 → `leave 40 ci`); следующий круг.
   - 5 кругов исчерпано → `leave 70 base-moving`.
3. `bin/git-auto-lib:ga_ci_wait` ветка `pr` (строки 136–163): необязательный 5-й аргумент `since`. При `since` и `sha` фаза появления: `runs=$(gh run list -R "$slug" --commit "$sha" --event pull_request --json status,createdAt)` и считать прогон появившимся только если есть элемент с `createdAt >= since` (`jq --arg s "$since" '[.[]|select(.createdAt>=$s)]|length'`). Без `since` — поведение прежнее.
4. `bin/ship-test.d/u17-base-move.sh` (образец `bin/ship-test.d/u8-ci-head.sh`, заглушка gh через `$d/runs-pr`): (а) `ga_ci_wait pr` с `since` позже `createdAt` старого прогона → 30 (старый не засчитан); (б) с новым прогоном `createdAt >= since` и checks pass → 0. Если поведение п.2 тестируется заглушками ship-test без сети — добавить (в) основа не сдвинулась → `pr merge` вызван, `pr close` не вызван; иначе ограничиться (а),(б) и написать почему.
