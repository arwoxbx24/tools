# ТЗ dcfg-8yqv4.38 — safe-delete branch: слитая локальная ветка без origin

## U1
Skills: ponytail:ponytail

Факт: `bin/safe-delete:204-205` — ветка без `refs/heads/<br>` на origin → `refuse "нет на origin"`. После `ship` origin-ветка удалена, PR MERGED, локальная ветка остаётся навсегда (5 веток `claude/dcfg-8yqv4.{30,31,33,34,35}-*`). Закон: `LAWS-PROCEDURES.md` §«Ветки агентов» стр. 69 — удалять только свою, после PR MERGED, после squash — `git update-ref -d refs/heads/<ветка> <headRefOid>`.

Правка только `bin/safe-delete` (режим `branch`), минимальная:
- если `shah` пуст (нет на origin): ветка считается слитой, когда локальный `sha=$(git rev-parse refs/heads/$br)` либо является предком `origin/main` (`git merge-base --is-ancestor`), либо (`SAFE_DELETE_GH=true`) равен `headRefOid` одного из `gh pr list --head "$br" --state merged --repo "$rr" --json headRefOid`;
- слитая → `git update-ref -d "refs/heads/$br" "$sha"`, строка в лог как у других удалений, rc 0; тег/бандл не нужны (содержимое уже в main / в PR);
- иначе — прежний `refuse "нет на origin: $br"` (rc 2). Проверки имён, `main|master|HEAD|codex/*`, открытых PR — без изменений и выполняются раньше.

Правка `bin/safe-delete-test`: добавить 2 проверки к существующим (режим `SAFE_DELETE_GH=false`, репо под /tmp):
- локальная ветка, слитая в origin/main и удалённая на origin → rc 0, `git branch --list` пуст;
- локальная ветка с неслитым коммитом, без origin → rc 2, ветка на месте.

Критерии:
1) `bash bin/safe-delete-test` → все PASS, итоговая строка показывает +2 проверки, 0 FAIL.
2) `git diff --stat origin/main` — только `bin/safe-delete`, `bin/safe-delete-test`, этот ТЗ; `bin/safe-delete` +≤12 строк.
3) Существующие отказы (main, codex/*, nope, refs/heads/…) — по-прежнему rc 2 (старые проверки теста зелёные).

Запреты: не удалять настоящие ветки в /root/workspaces/tools (это сделает главный агент после слияния); не трогать другие файлы, режимы `file`/`worktree`, pm2, хуки; без записи в bd; без сети.
