## U1 — behaviors (you design the code; smallest diff)

B1 (ADR-41, FR-046), `bin/ship-post`, delivery of one atom (`deliver_one`): when one delivery attempt of an atom ends with code 23, 70 or 75, the same call retries the attempt; at most 3 attempts in total, with a pause between attempts of `SHIP_POST_RETRY_PAUSE` seconds (default 30; the only new env var, tests set it to 0). An attempt is the existing delivery steps for the atom (remote state check and the `ship` call). Success on any attempt ends as today (receipt, close, live sync). After the 3rd failed attempt the failure is recorded exactly as today (`record_failure` → parking, incident, label). Every other code (0, 10, 20, 24, 30, 40, 50, 60, 71, 72, 80, 130, unknown) is not retried and is handled exactly as today. A parked atom is still never taken by a plain scan or `--watch` (keep the existing parked-skip line with `watch:-0` unchanged, exactly one occurrence of `watch:-0` in the file).

B2 (ADR-42, FR-047), `bin/ship`: the two places that exit with `70 ci-billing` (GitHub refused to start CI jobs) exit with code 72 instead (step name stays `ci-billing`). Update the exit-code list in `bin/ship` help/usage text: add `72 ci-not-started` and remove `ci-billing` from the 70 entry.

B3 (ADR-42), `bin/ship-post`: code 72 is INFRA and parks at once (no retry from B1). The incident/parking text for code 72 says: «GitHub не запускает CI репозитория; доставка — явным ship-post --atom <id>, когда CI репо снова запускается». If parking already handles unknown codes as INFRA, only add the code-72 text; do not change other codes' texts.
