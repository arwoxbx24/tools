Причина: 09.10 `bd find-duplicates` — 15 пар среди 6 задач ship-post (одна причина, exit 80) и 6 пар среди 4 задач `[GIT-SYNC]`. `record_failure` (`bin/ship-post:241-258`) ищет задачу по заголовку с атомом → каждый атом = новая задача. `bd_mark` (`bin/git-sync:11-14`) кладёт ref в заголовок → каждый ref после 24 ч = новая задача.

Правки:
1. `bin/ship-post`, `record_failure`:
   - заголовок `t="[ship-post] delivery failure $(basename "$repo") exit $rc"`;
   - поиск: `bd_cmd search "$t" --status open,in_progress,blocked --json`, затем существующий jq-фильтр точного заголовка;
   - нашли → `bd_cmd update "$issue" --append-notes "atom $atom sha $head exit $rc"`;
   - не нашли → `bd_cmd create "$t" …` с теми же флагами, что сейчас;
   - строки reopen атома, `--append-notes` атома, `dep add "$atom" "$issue"` и `touch "$marker.reported"` не менять.
2. `bin/git-sync`, `bd_mark`:
   - заголовок `t="[GIT-SYNC] $n $r"`;
   - всегда сначала `bd search "$t" --status open,in_progress,blocked --label git-sync --json` → jq точного заголовка;
   - нашли → `bd update <id> --append-notes "$stamp ${3:-}"`, return;
   - не нашли → прежняя проверка метки 24 ч; разрешено → `bd create -t chore -d "## Acceptance Criteria"$'\n'"Ссылка ${3:-} (статус $r) в каталоге $n проверена и разобрана (git show <ref>), запись закрыта с выводом команды." "$t" -l git-sync && touch "$mk"`;
   - `GA_NO_BD` по-прежнему выключает всё.

Запреты: только `bin/ship-post`, `bin/git-sync` и (U3) `.github/workflows/tools-smoke.yml`; без новых файлов в репо; тестовая обвязка — только в `/tmp`. Реальный трекер не трогать: перед каждым тестом `bd where` в scratch-каталоге не должен показывать `/root/workspaces/projects/.beads`. Для ship-post — `SHIP_POST_BEADS_ROOT=<scratch>`. Для `bd_mark` — scratch-каталог с `bd init`, cwd в нём, `GA_LOG_DIR=<scratch>/logs`. `rm -rf` вне `/tmp` запрещён. git commit не делать. Принципы: KISS, YAGNI, DRY, fail fast.

Критерии (вывод каждой команды — в evidence):
1. `bash -n bin/ship-post` и `bash -n bin/git-sync` rc 0.
2. scratch: два вызова `record_failure` (repo `tools`, rc 80, атомы A и B) → `bd search "[ship-post] delivery failure tools exit 80" --status open --json | jq length` = 1, notes содержат `atom A` и `atom B`.
