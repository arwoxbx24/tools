# ТЗ dcfg-8yqv4.12 — ship: классы репо plain/staged/guarded; защита вместо отказа; без CI — wait-owner вместо merge

## U1 — классификатор и два новых конечных состояния ship
Разведка — repowise; индекс: repowise/CBM проверен, нет — `tools/bin/code-memory-enable`.

Причина (spec:099 v4, ADR-14..16, FR-025..027; `projects/specs/099-ship-dev-prod/spec.md` раздел v4). Владелец 09.10 отменил исключения папок, но без настоящей проверки код сам на прод не идёт. Сейчас код делает два неверных действия:
- `bin/ship:56` отказывает кодом 10 репо с `ga_skip_reason`;
- `bin/ship:152-153` при `ci=none` в режиме one сливает в prod без тестов.

Решение (ADR):
1. `bin/git-auto-lib`: новая функция `ga_class <name> <mode>`, rc 0. Порядок проверок (закрыто по умолчанию):
   - `mode == two` → `staged`. Признак — `origin/dev`, её заводят явно по слову владельца, для hh-scoring — по согласию его оператора (spec:099 v5);
   - иначе `ga_skip_reason "$name"` не пуст → `guarded`. `pushurl` не учитывается: отсутствие заглушки — не разрешение (hh-scoring-dev без заглушки, замер 09.10);
   - иначе `plain`.

   Шлюз prod: `plain` с CI → `auto`; все прочие → `owner` (ADR-17).
2. `bin/ship`:
   - строку `:56` удалить;
   - после `read -r mode base prod` (`:61`) и проверки базы вставить `class=$(ga_class "$name" "$mode")` и `gg_log 0 "class=$class"`;
   - класс `guarded` прерывает ship сразу после блока локального коммита (`:79-94`, до `locked_core`). Действия: `g update-ref "refs/dev-ready/$branch" HEAD`, `echo "prod:hold guarded $(ga_skip_reason "$name")"`, `leave 0 prod-hold`. До этого места у `guarded` не должно быть `gh`, `push` и `fetch`.
3. `bin/ship`, путь `wait-owner`. Отказ режима two (`:131-134`) не трогать. В режиме one ветку `if [[ $ci == none ]]; then echo ci:none` (`:152-153`) заменить. Новые действия:
   - `echo ci:none` (только при `ci == none`);
   - `echo 'prod:wait-owner no-ci'`;
   - `g update-ref "refs/dev-ready/$branch" "${expected_head:-HEAD}"`;
   - `bd update "$atom" --append-notes "wait-owner no-ci: PR https://github.com/$slug/pull/$num — без автопроверок, на прод только ship-promote по слову владельца" >/dev/null 2>&1 || true`;
   - `leave 0 wait-owner`.

   Merge, `bd close`, live sync и уборка worktree в этом пути не выполняются.
4. Остальное не менять. `ship-promote`, `ship-post`, `git-sync` и `git-state` не трогать.

Тесты — `bin/ship-test` и `bin/ship-test.d/`:
- Проверка 7 (`stroyremont`, сейчас ждёт rc 10). Новое ожидание:
  - rc 0, в выводе `prod:hold guarded`;
  - `git -C "$GA_PROJECTS/stroyremont" rev-parse --verify refs/dev-ready/claude/z` успешен;
  - в bare `origin-sr.git` нет ветки `claude/z`;
  - журнал stub `gh` за этот вызов пуст.
- Проверки 9 и 18 (`ci:none` → merge). Новое ожидание:
  - rc 0, в выводе `prod:wait-owner no-ci`;
  - merge в журнале stub `gh` отсутствует;
  - worktree на месте;
  - ветка агента запушена в origin.

  Для 9 условие `head == merge-sha` и `! -d $r9` заменить на это. Для 18 сохранить проверку `anc == 1`.
- Новая проверка (следующий свободный номер): `ga_class` для пяти входов:
  - `x one` → `plain`;
  - `x two` → `staged`;
  - `stroyremont one` → `guarded`;
  - `hh-scoring-dev one` → `guarded`;
  - `stroyremont two` → `staged`.
- Новая проверка: `hh-scoring-dev` без `pushurl`, режим one → rc 0, `prod:hold guarded`, журнал stub `gh` пуст, push 0.
- Прочие проверки не ослаблять. `bash bin/ship-test` → `PASS N/N`.

Дока: если в `origin/main` есть `docs/ship-post-ARCHITECTURE.md` (атом dcfg-e3kyr), обновить в ней описание шагов ship: класс, `prod-hold`, `wait-owner`. Иначе CI-гейт `ship-doc-check` отклонит PR.

Запреты: только `bin/git-auto-lib`, `bin/ship`, `bin/ship-test`, `bin/ship-test.d/*`, `docs/ship-post-ARCHITECTURE.md` и этот ТЗ. Без `--force`, `reset --hard`, `rm -rf` вне `/tmp` и без новых зависимостей. Принципы: KISS, YAGNI, fail fast.

Критерии:
1. `bash -n bin/ship bin/git-auto-lib` → rc 0.
2. `bash bin/ship-test` → `PASS N/N`, rc 0.
3. `grep -c 'ga_skip_reason' bin/ship` = 1 (только в строке `prod:hold`); `grep -c 'leave 0 wait-owner' bin/ship` = 1; `grep -c '^ga_class()' bin/git-auto-lib` = 1.

Паспорт: `bin/ship:48-70,72-94,122-163`; `bin/git-auto-lib:79-97`; `bin/ship-test:205-260,300-316`.

## Уточнение после первого прогона (единственный повтор канала)
Состояние правок в worktree принять за основу, не переписывать. Единственный сбой `bash bin/ship-test`: проверка 19 (U4, код-архив) — `FAIL 19`, `ship` в положительном случае вернул rc=50 (merge) вместо 0. Причина-гипотеза: stub `gh` хранит признак созданного PR в `$GH_CREATED` (`bin/ship-test:29,40`), а новые проверки 9 и 18 больше не доходят до merge, и признак остаётся для проверки 19. Исправить в `bin/ship-test`: сбросить `rm -f "$GH_CREATED"` (и при необходимости `: > "$GH_JOURNAL"`) перед блоками 19 (отрицательным и положительным), как уже сделано перед проверкой 10. Если гипотеза неверна — найти причину rc=50 (`bash -x bin/ship-test`, блок после `mkrepo r19 1`) и устранить в разрешённых файлах. Ослаблять проверку 19 нельзя. Итог: `bash bin/ship-test` → `PASS N/N`, rc 0.

## Уточнение 2 — причина доказана (главный агент, 10.10)
Замер: копия `bin/ship-test` с выводом ship проверки 19 в файл. Вывод: `pr:7` и `ship: gh: fatal: invalid refspec 'refs/heads/:refs/remotes/origin/'`.

Механизм:
- `$GH_CREATED` остался от предыдущей проверки, поэтому stub `pr list` отвечает `7` и `pr create` не вызывается;
- журнал `$GH_JOURNAL` очищен новыми строками `: > "$GH_JOURNAL"`;
- stub `pr merge` берёт базу из последней строки `pr create` журнала (`bin/ship-test:80`), получает пусто, и `fetch` падает → ship rc 50.

Исправление — ровно две строки в `bin/ship-test`, больше ничего не менять: `rm -f "$GH_CREATED"` непосредственно перед `( cd "$w20" && …ship… )` и перед `( cd "$w19" && …ship… )` (сейчас строки ~362 и ~370). Итог: `bash bin/ship-test` → `PASS N/N`, rc 0.
